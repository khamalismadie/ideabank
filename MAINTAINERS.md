## Responsibilities

Maintainers are responsible for:

- Reviewing and merging pull requests
- Triaging issues
- Setting project direction
- Maintaining code quality
- Ensuring timely releases

## Becoming a Maintainer

Contributors who have made significant, sustained contributions may be invited to become maintainers. This requires:

1. At least 10 merged pull requests
2. Demonstrated understanding of the codebase
3. Active for 3+ months
4. Nomination by an existing maintainer
5. Approval by majority of current maintainers

## Communication

- **GitHub Issues**: Bug reports, feature requests
- **GitHub Discussions**: Questions, ideas
- **Email**: maintainers@ideabank.dev

## Release Process

See [VERSIONING.md](VERSIONING.md) for release procedures.

## Conflict Resolution

1. Discussion on GitHub
2. If unresolved, maintainer vote
3. If tied, lead maintainer decides
